# Taste
- Expects every UI component to be fully adapted to dark mode (dark: variants for text, backgrounds, hovers, borders, placeholders, disabled and error/helper states), pointing out individual files that still lack it as a defect to fix on the spot. Confidence: 0.85
- Field labels must come from the base input components' `label` prop (InputText, InputNumber, InputEmail, InputPassword, InputDate, InputTextArea, Select, Checkbox) rather than a separate external `<label>`, `<span>` or `<div>`; text, ids, required markers, hint/helperText stay preserved. Confidence: 0.8
- Wants pages and business components to reuse the project's existing UI components (Button, Select, Input*, Checkbox, DataTable, ModalGrid/Dialog, Accordion, PillsBadge) instead of raw native `<button>`, `<select>`, `<input>`, `<table>`, div-built modals or `<span>`-with-classes pseudo-components — native markup is only acceptable inside the base UI components themselves, and a cleanup is not considered done while any raw markup remains. Visual variants (colors, spacing, typography) must be centralized in the base component's style map and referenced by a semantic prop, never re-declared per screen; new variants go in the base component once rather than via new libs or duplicate components. Confidence: 0.88
- Expects actual code edits as the deliverable — explicitly rejects receiving only a diagnosis or an implementation plan. Confidence: 0.72
- Work must end with a written wrap-up: a summary of the changes made plus the actual lint/test/build results (and honest mention of pre-existing failures), and the agent must never manually start deploys or CI workflows. Confidence: 0.7
- Communicates in Brazilian Portuguese and expects replies, explanations and progress reports in Portuguese. Confidence: 0.7
